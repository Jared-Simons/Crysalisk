Issues:

General:

The Logging system is not very flexible yet - it relies on ALWAYS having at least one logger active at index 0 of its registry... there should be a fall-through case of calling the platform layer otherwise.

The custom containers are dynamicially allocating from malloc, this should be switched to our own memory system.

FileSystem:

Filesystem currently only opens files in either read OR write mode... can't do both.

CVector:

Trying to pass a CVector by value to create a copy will result in heap-corruption, as the copy was not allocated (but taken by reference) - thus trying to free a non-existent allocation will wreak havoc.
	Need to nail down pass-by-value vs pass-by-reference with CVector.
	
Passing CVector to a function with 'const' does not work yet - this should be prioritized going forward.


CSet:

Creating a CSet<uint32_t> does not work -- need to rework this data structure as we move forward.


Vulkan Renderer:

Device creation slows the application down quite a lot, way more than it should.
I suspect this has to do with checking for device extensions (string comparisions in a loop of well over 100 iterations).
This is NOT fatal or to be prioritized, but should be fixed when possible.

Device Creation - Selecting Queue Family Indices is possibly flawed (selecting the last one possible), need to revisit this in the future.

There are some Validation Errors when the framebuffer gets resized in regards to the semaphore objects. Very inconsistent and not sure how exactly to fix at this time. Maybe just disable the rendering loop while dragging the window?
Also - Minimizing the window causes an endless stream of validation errors

Vulkan rendering backed is not currently being allocated from our internal memory system.


UnitTests:

The Premake Script is not properly setting the working directory for the UnitTests module, which will cause the debugger to fail when running.

The UnitTests project CANNOT be ran in Release mode currently, it crashes on the call to Engine->Shutdown().
